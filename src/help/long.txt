git-compose-commit - build a message and run git commit

Usage: git-compose-commit [COMPOSE OPTIONS] [GIT OPTIONS] [-- PATHSPEC...]

HOW IT WORKS

  The subject is first. Other sections keep argument order and are separated
  by blank lines. Normally the tool writes a temporary message file and runs
  git commit -F with it. Git handles its normal cleanup and hooks; options
  such as --all and --signoff pass through. Use -- PATHSPEC... for paths.
  Do not pass Git's -m or -F options; the tool supplies the message file.

  --stdout and --output FILE both skip git commit entirely. Preview first,
  then rerun without the output option to commit. Output modes cannot be
  combined with Git commit options.

MESSAGE OPTIONS

  --subject TEXT       Subject line; may appear once
  --text TEXT          Paragraph; normalize whitespace and wrap at the margin
  --detail TEXT        Preserve line breaks and indent every line four spaces
  --line TEXT          Add one unwrapped line; no embedded newline
  --field KEY:VALUE    Add an aligned key/value row
  --note TEXT          Add a wrapped Note: paragraph
  --warning TEXT       Add a wrapped Warning: paragraph
  --wrap-width N       Set wrapping and alignment margin (20-256; default 72)

  Repeat --text, --detail, and --line to add more sections. Adjacent --field
  options form one block. A field splits at its first colon; both sides must
  be nonempty. Words longer than the margin remain intact.

OUTPUT AND CONTROL

  --stdout             Print the message to standard output; skip git commit
  --output FILE        Write the message to FILE; skip git commit
  --rand-seed N        Repeat random bubble choices with the same seed

  --stdout is the portable equivalent of --output /dev/stdout. --output
  overwrites an existing file. The two output modes cannot be combined.
  With the same configuration and arguments, a seed repeats random choices.

TABLES

  --table-head CELLS   Start a table with comma-separated headings
  --table-row CELLS    Add a comma-separated row to that table
  --table-rows ROWS    Add several semicolon-separated rows

  Rows must match the number of headings. Cells are trimmed and sized to fit.
  CSV quoting and escaping are not supported. --th and --tr are shorter
  aliases for --table-head and --table-row.

LISTS

  --list-item TEXT     Add an item; starts a numbered list if needed
  --numlist            Start a numbered list (also --list=numbered)
  --bullets            Start a bullet list (also --list=bullets)
  --list KIND          Start a numbered or bullets list
  --list-end           Return to the parent list

  Starting a list inside a list nests it. --list-end returns to the parent;
  the next message section closes open lists.

FOOTERS

  --footer-N TEXT      Define footer N for a [#N] reference

  References are scanned in --text and --line. Every reference needs a footer,
  and every footer must be referenced. Backtick-quoted references are ignored.

BAR CHARTS

  --hbar-chart DATA    Add a horizontal ASCII bar chart
  --vbar-chart DATA    Add a vertical ASCII bar chart

  Bar charts need at least two label:value items with nonnegative integers.
  Horizontal width defaults to 24; vertical height defaults to 6. Sizes range
  from 1 to 256. Settings use semicolons; with settings, use data=... . float
  accepts left, center, or right. Charts default to center.

LINEAR FLOW CHARTS

  --hflow-chart DATA   Add a horizontal chain of boxes
  --vflow-chart DATA   Add a vertical chain of boxes

  Flow chains need at least two comma-separated labels. Without settings,
  pass the labels directly. With settings, use semicolons and data=... .
  float accepts left, center, or right and defaults to center. Box labels
  remain on one line.

BRANCHING FLOWCHARTS

  --flow-chart OPTIONS    Start a directed graph (requires Graphviz's dot)
  --flow-node ID:TEXT     Add a box
  --flow-decision ID:TEXT Add a decision shape
  --flow-terminal ID:TEXT Add a rounded start/end shape
  --flow-edge EDGE        Connect shapes, as in 'start -> done'

  First name the shapes, then connect their IDs with --flow-edge. You can
  label a link with [label="yes"] or join a chain with A -> B -> C. IDs start
  with a letter or underscore and may contain letters, digits, and underscores.
  A graph needs at least two shapes and one link. The next message option
  closes it; graphs cannot be nested.

  Set direction=vertical|horizontal (default vertical) and
  float=left|center|right (default center). nodesep=N and ranksep=N adjust
  spacing; both accept numbers greater than zero through 10. The tool builds
  DOT internally, so arbitrary DOT source is not accepted.

SPEECH AND THOUGHT BUBBLES

  --bubble OPTIONS     Add an ASCII bubble with a speaker

  Pass plain text for the phrase, for example --bubble 'Hello there!'.
  Unless the value starts with a recognized name= clause, it is all text.
  For explicit settings, use name=value clauses separated by semicolons:
    phrase=TEXT         Required; the words in the bubble
    speaker=NAME        cat, dog, or stick-figure
    style=STYLE         speech (also voice) or thought
    speaker-side=SIDE   below (default), left, or right
    bubble-side=SIDE    left, center, or right relative to the speaker
    float=SIDE          left, center, or right in the message margin

  Unspecified speaker, style, bubble-side, and float values are random unless
  set in ~/.compose-commit.toml. --rand-seed makes the choices repeatable.
  Explicit settings always win over configured defaults. Speech bubbles above
  a speaker use one slash aimed at the head; thought bubbles use dots.

ALIASES, DEFAULTS, AND HELP

  Compose options accept --option=value or --option value. Every compose
  option also has a --compose- prefixed form, such as --compose-subject and
  --compose-stdout. Use prefixed forms in scripts to avoid collisions with
  future Git options.

  ~/.compose-commit.toml may set wrap_width, rand_seed, bubble_speaker,
  bubble_style, bubble_speaker_side, bubble_side, and bubble_float. CLI values
  override them. See the README for a configuration example.

  -h, --help=short     Show the quick synopsis
  --help, --help=long  Show this guide
  --man                Show this same guide
  --help=TOPIC          Show one topic with its examples:
                        message, output, tables, lists, footers, charts,
                        flowcharts, bubbles, or examples
  --version            Show the installed package version

EXAMPLES

  1. Basic commit. This runs git commit on tracked changes (--all):
     git-compose-commit --subject 'Refresh cache' \
       --text 'Keep cached values in sync after each write.' --all

     Message:
       Refresh cache

       Keep cached values in sync after each write.

  2. Preview only. --stdout prints the composed message and skips Git:
     git-compose-commit --subject 'Refresh cache' \
       --text 'Keep cached values in sync after each write.' --stdout

     Output:
       Refresh cache

       Keep cached values in sync after each write.

  3. Fields and a note:
     git-compose-commit --subject 'Document settings' \
       --field 'Backend:sqlite' --field 'Retries:3' \
       --note 'Keep the old config readable.' --stdout

     Output:
       Document settings

       Backend: sqlite
       Retries: 3

       Note: Keep the old config readable.

  4. Table:
     git-compose-commit --subject 'Table' --table-head 'Name,State' \
       --table-row 'cache,ready' --table-row 'worker,waiting' --stdout

     Output:
       Table

       +--------+---------+
       | Name   | State   |
       +--------+---------+
       | cache  | ready   |
       | worker | waiting |
       +--------+---------+

  5. Nested list:
     git-compose-commit --subject 'Refresh cache safely' --numlist \
       --list-item 'Write the new value' --bullets \
       --list-item 'Keep readers on the old value' --list-end \
       --list-item 'Publish the new value' --stdout

     Output:
       Refresh cache safely

       1. Write the new value
         * Keep readers on the old value
       2. Publish the new value

  6. Numbered footer:
     git-compose-commit --subject 'Footer' \
       --text 'Validated [#1].' --footer-1 'Using the new parser.' \
       --stdout

     Output:
       Footer

       Validated [#1].

       [#1] Using the new parser.

  7. Horizontal bar chart:
     git-compose-commit --subject 'Chart' \
       --hbar-chart 'float=left;width=10;data=tests:10,docs:5' --stdout

     Output:
       Chart

       tests | ########## 10
       docs  | ##### 5

  8. Vertical bar chart:
      git-compose-commit --subject 'Test coverage' \
        --vbar-chart 'float=left;height=5;data=tests:10,docs:5' \
        --stdout

      Output:
        Test coverage

        10 |   #
           |   #
           |   #     #
           |   #     #
           |   #     #
         0 +------------
            tests docs

  9. Linear flow chart:
     git-compose-commit --subject 'Flow' \
       --hflow-chart 'float=left;data=Parse,Validate' --stdout

     Output:
       Flow

       +----------+     +----------+
       |  Parse   | --> | Validate |
       +----------+     +----------+

  10. Vertical flow chart:
      git-compose-commit --subject 'Release flow' \
        --vflow-chart 'float=left;data=Input,Transform,Output' --stdout

      Output:
        Release flow

        +-----------+
        |   Input   |
        +-----------+
              |
              v
        +-----------+
        | Transform |
        +-----------+
              |
              v
        +-----------+
        |  Output   |
        +-----------+

  11. Branching flowchart. Install Graphviz so dot is on PATH:
     git-compose-commit --subject 'Branch' \
       --flow-chart 'direction=horizontal;float=left' \
       --flow-terminal 'start:Start' --flow-terminal 'done:Done' \
       --flow-edge 'start -> done' --stdout

     Output:
       Branch

       (-------)                (------)
       ( Start )--------------->( Done )
       (-------)                (------)

  12. Speech bubble with a chosen speaker and placement:
      bubble='speaker=cat;style=speech;phrase=Hi;speaker-side=below'
      bubble="$bubble;bubble-side=center;float=left"
      git-compose-commit --subject 'Bubble' --wrap-width=72 \
        --bubble "$bubble" --stdout

      Output:
        Bubble

         .--.
        ( Hi )
         '--'
           \
         /\_/\
        ( o.o )
         > ^ <

  13. Thought bubble with a stick figure:
      bubble='speaker=stick-figure;style=thought;phrase=Maybe'
      bubble="$bubble;speaker-side=below;bubble-side=center;float=left"
      git-compose-commit --subject 'Consider the change' --wrap-width=72 \
        --bubble "$bubble" --stdout

      Output:
        Consider the change

        ( Maybe )
            O
            o
            .
            O
           /|\
           / \

  14. Combine paragraphs, fields, lists, and footers:
      git-compose-commit --subject 'Validate cache writes' \
        --text 'Check input before publishing [#1].' \
        --field 'Result:ready' --bullets --list-item 'Parse' \
        --list-item 'Validate' --footer-1 'Readers see only valid data.' \
        --stdout

      Output:
        Validate cache writes

        Check input before publishing [#1].

        Result: ready

        * Parse
        * Validate

        [#1] Readers see only valid data.
